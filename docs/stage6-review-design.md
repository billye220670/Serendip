# 阶段 6 — 评审滑卡模式 · 设计文档

> 状态：**设计定稿，待实现**（三项决策已确认，见文末 §11）。
> 角色视角：UX 设计师 + 产品经理。决策都给了理由，标 ⭐ 的是采纳方案。
> 实现提示：动手前先出一份落地计划（plan）过目——本文是"做什么"，plan 是"怎么落地"。

---

## 1. 目标与定位

| | 探索（Explore） | 评审（Review） |
|---|---|---|
| 形态 | 瀑布流，多图并列 | 单卡居中，一次一张 |
| 心智 | 逛 / 重新发现（feed） | 做决定 / 给库"理货"（triage） |
| 节奏 | 随便滚、随便看 | 快速判断，一张接一张 |
| 主要动作 | 看、偶尔标记 | 喜欢 / 不感兴趣 / 跳过 |

一句话定位：**评审是"专注判断"模式**——把注意力收束到一张图上，用最低的操作成本快速给出态度。探索是广度，评审是深度 + 决断。

---

## 2. 核心交互：手势 + 按键映射（对齐 Tinder / 探探）

> 设计原则：**水平轴 = 决定，严格照搬市面标准**（右=正、左=负），不自创方向语义。

| 动作 | 手势 | 按键 | 依据 |
|---|---|---|---|
| **喜欢** | 右滑 → | `→` | Tinder/探探：右滑 = like |
| **不感兴趣** | 左滑 ← | `←` | Tinder/探探：左滑 = nope/pass |
| **加入分类** | 上滑 ↑ | `↑` | 对应 Tinder 上滑"超级喜欢"的**强意图槽位**：一个比 like 更主动的"我要收好它"动作 |
| **跳过** | —（不占方向） | `Space` | Tinder 桌面端 `Space` = 中性"下一张"，语义天然契合"先放着、待会再说" |
| **撤销上一张** | — | `Backspace` | 对应 Tinder Rewind；方向键已被占满，撤销不该是方向 |

设计取舍：
- **跳过不给方向手势**：跳过是"不做决定"，本质是"轻点前进"而非"甩出一个态度"，所以只给 `Space` + 中央按钮。下滑方向**有意保留不用**，避免硬塞一套"上下左右"。
- **上滑 = 加入分类**，而不是"跳过"：因为 Tinder 上滑的心智是"更强的正向"。若把上滑当跳过，会和用户肌肉记忆冲突（上 = 更喜欢，不是"算了待会看"）。把这个槽位给"加入分类"恰好——它就是一个更主动的收藏/归档动作。

底部按钮区从左到右镜像手势顺序（与卡片飞出方向一致，强化映射）：
`[撤销]  [不感兴趣 ✕]  [跳过 ⤼]  [加入分类 ＋]  [喜欢 ♥]`

---

## 3. 各动作语义

- **喜欢**：`setLiked(id, true)`，卡片右飞，前进。
- **不感兴趣**：`setDisliked(id, true)`，卡片左飞，前进（与探索一致：以后基本不再出现）。
- **跳过**：**不写库**，直接前进。靠 recommender 的冷却（取卡时已更新 `last_shown_at`）让它自然过段时间再出现 = "待会再判断"。这正是设“跳过”的意义：不逼用户二选一。
- **加入分类**：上滑/＋ 打开**复用阶段 5 的 `ContextMenu` 分类快选**；选完归类并前进。**与 like/dislike 正交**——归类不顺带改喜欢态度（避免意外副作用）。无分类时该动作降级为提示"先建分类"。
- **撤销**：退回上一张，并**回滚它刚才的库改动**（喜欢/不感兴趣还原；归类移除；跳过仅退回不需回滚）。

---

## 4. ⭐「快速加入分类」必要性论证（PM 结论）

你的疑虑成立：探索广场已能很轻松地多选 + 拖拽/菜单批量归类。那评审里还要不要？

**论证：**
- 反方（不做）：评审的价值是"快"，binary 决断越纯越爽；归类会打断节奏；批量归类探索已覆盖。
- 正方（要做）：评审是**唯一"逐张专注凝视"的时刻**——正是产生"这张该进『旅行』"判断的最佳时机。探索是"逛"，往往没在做归类决策。
- 关键洞察：矛盾不在"要不要"，而在"**会不会拖慢快路径**"。

**结论：做，但只放在"慢路径"，绝不挡快循环。**
- 快循环永远是 →/←/`Space` 三键，零打断。
- 加入分类只在你**主动上滑/点＋**时出现（复用现成 picker，开发成本极低，且刚好填上 Tinder 上滑那个本就该有的"强正向"槽位）。
- 这样它"想用时在、不用时隐形"，既兑现了评审的判断价值，又尊重了你"别把快路径搞臃肿"的担忧。

> 备选：若你仍想砍，v1 可去掉它（上滑改 = 跳过），后续再补。但我建议保留——边际成本几乎为 0，收益是评审专注时刻的归档能力。

## 5. ⭐ 数据来源与路径（回答"是否和探索同一路径"）

**结论：复用探索的同一套推荐引擎（`getRecommendations`），但各自独立成局。** 同意你的方向，并补一个 PM 层面的边界说明：

- **复用什么**：同一个 `recommend()` 两级加权抽样大脑。不另造第二套采样器——浪费且行为会漂移。喜欢/不感兴趣也走探索同款 `setLiked`/`setDisliked`。
- **怎么呈现**：评审维护一个**小缓冲队列**（如一次取 10 张），一次显示一张，飞走就推进、见底就再取。"一个采样大脑，两种呈现：网格=探索、卡片=评审"。
- **独立成局**：评审有自己的缓冲与游标，**不和探索共享同一个滚动光标**——否则你在评审里翻的会污染探索的 feed 位置。两者从同一引擎**各自独立取数**即可（DB 状态天然共享，这没问题也正是我们要的）。
- **可选增强（标记为后续）**：给评审加一个"偏向未评级（`liked=0 AND disliked=0`）"的过滤，让评审真正在"消化待判断积压"。v1 直接复用探索流最省事；这个 bias 是低成本的二期增强。

## 6. 撤销栈

- 维护一个**已判定卡片的栈**（含卡片数据 + 本次动作 + 回滚所需信息）。
- `Backspace` / [撤销] 弹栈：把该卡重新置于当前卡之前，并反向调用对应 IPC（取消喜欢/取消不感兴趣/从分类移除）。
- 只保留有限步（如最近 10 步）即可，够覆盖"手滑"场景。

## 7. 布局骨架

```
┌───────────────── 评审 ─────────────────┐
│                  12 / 待判断             │  ← 顶部：进度/计数（轻量）
│                                          │
│            ┌──────────────┐              │
│            │              │              │
│            │   当前卡片    │  ← 拖拽时跟手倾斜，                  │
│            │  (图/视频)    │     露出 LIKE / NOPE / 分类 角标      │
│            │              │              │
│            └──────────────┘              │
│         （下一张在底部露一点边）          │  ← 卡堆暗示还有更多
│                                          │
│   [↶]   [✕]    [⤼]    [＋]    [♥]        │  ← 底部按钮，镜像手势
└──────────────────────────────────────────┘
```
- 视频卡：评审是专注场景，可直接自动静音循环播放（不像探索要省资源限播）。
- 拖拽跟手 + 角标（右滑浮现绿色 LIKE、左滑红色 NOPE、上滑分类标），即时反馈方向。

---

## 8. 边界 / 空态

- 无根目录 / 未扫描：与探索一致的空态引导。
- 队列取尽（recommender 冷却饱和，返回为空）：显示"暂时没有更多可评审的了"。
- 无分类时上滑/＋：toast 提示"先在左侧新建一个分类"。

## 9. 技术落点（复用为主）

- **路由**：`useLibraryStore` 的 `view` 增加 `{ kind: 'review' }`；侧栏现有"评审"`NavItem`(Star) 接上 `setView`。
- **复用**：`getRecommendations` / `setLiked` / `setDisliked` / `addItemsToCategory` / `ContextMenu`（分类快选）/ `serendip://` 取图取视频，全部现成。
- **新增**：`views/Review.tsx`（单卡 + 队列 + 撤销栈 + 键盘/手势）。已确认 package.json **无动画库**（只有 `@dnd-kit`），按"无新依赖优先"原则：滑动用**手写 CSS `transform` + 原生指针事件**（`pointerdown/move/up` 跟手位移 → 松手判定阈值 → 飞出动画用 CSS transition）。dnd-kit 是为"拖到投放目标"设计的，不适合这种"全卡跟手 + 阈值判定"的滑卡，因此评审不复用 dnd-kit，自己处理指针。
- **几乎不动后端**：跳过/撤销都在前端用既有 IPC 组合实现，无需新 IPC（除非二期做"未评级 bias"，那时给 recommender 加一个 `onlyUnrated` 选项）。

## 11. 已确认决策（v1 基线）

1. **加入分类：保留**，仅在慢路径（上滑 ↑ / ＋ 按钮）出现，复用阶段 5 的 `ContextMenu` 分类快选；不挡 →/←/Space 快循环。
2. **键位/手势：**`→` 喜欢 / `←` 不感兴趣 / `↑` 加入分类 / `Space` 跳过 / `Backspace` 撤销。左右上严格照搬 Tinder/探探，跳过不占方向、下滑保留不用。
3. **数据来源：**复用探索的 `getRecommendations` 引擎，评审独立缓冲与游标（不共享滚动位置）；v1 不加"未评级偏向"过滤（列为二期）。
