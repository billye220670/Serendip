# 阶段 8 — 画布模式（Canvas） · 需求文档

> 状态：**需求草案，待评审**。
> 角色视角：UX 设计师 + 产品经理。本文聚焦"做什么 / 用户怎么用"，技术只到落点级别（哪些复用、哪些新写），不展开实现细节。
> 体例对齐：[stage6-review-design.md](./stage6-review-design.md)。

## 1. 目标与定位

**画布是"长期收集 + 排版"的容器，跟探索/喜欢/分类/评审都不冲突。**

| | 探索 / 喜欢 / 分类 | 评审 | 画布 |
|---|---|---|---|
| 心智 | 浏览 + 偶尔归档 | 逐张做决定 | 自由排版、参照、灵感板 |
| 形态 | 瀑布流 | 单卡 | 自由二维平面（无限画布） |
| 主要动作 | 看、加心、归类 | →/←/↑/Space | 拖、缩、旋、裁、叠层 |

一句话定位：**像 PureRef 一样，把素材丢上一张可无限缩放的画布做参考拼图**，再叠两个 PureRef 没有的本地能力——**视频元素** 与 **摄影机手摇**。

---

## 2. 不打断浏览的整体形态（D 方向最终版）

> 我们采用了讨论里 D 的方案：**侧栏画布分组 + 全 Pane 视图 + 多种添加路径**。否决了 A（顶部 tab，跟自绘标题栏冲突）和 B（多窗口，跨窗口拖拽对 dnd-kit 是坑）。

### 2.1 侧栏入口（与 Categories 平级）

左侧栏底部新增 **"画布"** 分组，与 Categories 一样：
- 列出全部画布 pill；单击切换 `view = {kind:'canvas', id}`，沿用现成 sticky-sidebar 路由
- 右键：重命名 / 删除（复用 `PromptDialog` / `ConfirmDialog`）
- 拖拽重排（复用 `useSortable`）
- 媒体可拖入 pill（复用 `useDroppable`），加入该画布

> 画布天然是"集合"，且和分类一样会自然分化（旅行画布 / 灵感板 / 参考墙）。Schema 一开始就做成 `canvases` + `canvas_items` 多对多，避免日后迁移。

### 2.2 进入画布是 Pane View，不是 Modal

- 切到画布**不卸载** Explore / Category 的滚动位置（已通过 `useLibraryStore.view` + 现有探索保留浏览进度的机制实现）
- 画布是个长任务（要工具栏、缩放控件、辅助线），Modal 套这些会拥挤、Esc 误触代价高，所以走 Pane

### 2.3 添加路径（多入口都通向同一个"加入画布"动作）

| 入口 | 触发 | 行为 |
|---|---|---|
| **卡片悬浮按钮** | 探索/喜欢/分类瀑布流卡片右下角加图标（与 ❤️/👎 同组） | 单击直接加入"当前画布"（详见 §2.4） |
| **拖拽到侧栏 pill** | 复用现成 dnd 流程 | 多选时整组一起加（复用 stage 5 多选 + `DragPreview` 计数标） |
| **多选工具栏** | `SelectionToolbar` 加 "加入画布" 按钮 | 同卡片按钮规则 |
| **大图详情工具栏** | Detail 视图加同款图标 | 同上 |
| **画布内本身** | 把库里的素材拖到画布空白处（v2，先用前 4 条覆盖） | — |

### 2.4 「当前画布」机制（核心：让快速加入零打断）

为了避免"每次加入都要选画布"和"加入后强制跳转打断心流"两个反面，引入一个全局的"**当前画布**"指针（`currentCanvasId: number | null`，存在 zustand store）。

**指针如何变化**：
1. **进入某个画布**（侧栏点 pill / 通过任何路径切到 `view = {kind:'canvas', id}`）→ 自动成为当前画布
2. **新建画布** → 自动成为当前画布
3. **侧栏 pill 右键菜单**有"设为当前画布"——用于"我不想进去看，只想先设一下收集目标"的场景

**所有"加入画布"按钮统一行为**：

| 状态 | 行为 |
|---|---|
| **有当前画布** | 单击直接加入 → toast `"已加入『XXX 画布』"`，toast 右侧带"前往"链接（点了才跳，默认不跳） |
| **无当前画布** | 单击弹 `ContextMenu` picker（列所有画布 + "新建画布"项）；选完该项自动成为当前 |
| **想临时换目标加一次** | `Alt + 点击`（或长按）强制弹 picker；选完**不改变**当前画布 |

**让用户随时知道"当前是哪个"——双重视觉锚点**：

- **侧栏当前画布 pill**：左侧竖条 accent 色 + 背景微高亮（沿用"当前选中分类"的视觉语言）
- **Header 右侧 chip**（`gridSize` toggle 左边）：`当前: 『旅行画布』 ✕`
  - 点击 chip → 弹快速切换菜单（同 picker）
  - 点 `✕` → 清除当前画布，下次加入回退到弹 picker
  - 无当前画布时 chip 不显示（或灰态"未设定画布"，待视觉评审定）

**前往查看的三条路径**（都不强制）：
1. Toast 的"前往"链接
2. 侧栏 pill 单击（本来就是）
3. Header chip 点击切换菜单里的"前往当前"

> 心智模型："**当前画布 = 我刚进去看的 / 刚新建的那个**"。不需要"图钉"这种额外抽象，进去看就是了，自然而然。

## 3. 画布内核心交互（参考 PureRef，做适当删减）

### 3.1 视口（Pan / Zoom）—— 优先把手感打磨好

PureRef 的"丝滑感"来自三件事，我们都要做到：

1. **Zoom 锚点 = 鼠标位置**。滚轮上下缩放，画面以光标下的世界坐标为不动点（不是中心、不是原点）。
2. **缩放是连续的、无步进的**。`scale` 用浮点；可设上下限（建议 0.05x – 32x）。
3. **Pan 多入口**：
   - 中键拖动 = pan
   - `Space` 按住 + 左键拖动 = pan（兼容触摸板用户）
   - 触摸板双指拖 = pan（监听 `wheel` + `ctrlKey/metaKey` 区分 zoom/pan，标准做法）
   - **不做** 惯性滑行（PureRef 也不做，长期排版用反而会"漂"）

> 📌 视口 transform 不进入持久化的 item 数据；它存在 `useCanvasViewport` store 里，每张画布**记住自己的视口位置**（切走再切回来，画面停在原位）。

### 3.2 选择

| 操作 | 行为 |
|---|---|
| 左键单击元素 | 选中单个；点空白处取消选中 |
| 左键空白拖 | **框选（lasso/marquee）**：与矩形相交即入选 |
| `Shift` + 单击 / 框选 | 加入选区 |
| `Ctrl/Cmd` + 单击 | 切换该项 |
| `Ctrl/Cmd + A` | 全选 |
| `Esc` | 清空选区 |

> 复用 stage 5 的"selection store 用 Set + 返回新 Set 触发更新"模式，但**画布有自己的 selection store**（`useCanvasSelectionStore`）—— 跟瀑布流多选生命周期不同，混用会互相污染。

### 3.3 移动 / 缩放（变换手柄）

> **技术决策（已确认）**：变换手柄 / 旋转 / 锚点映射 / 多选包围盒等交互**引入 `react-moveable`（KaKao 维护，npm 周下载 50 万+）**。理由：这些几何规则设计 §3.3–3.4 列的每条它都原生支持，且与 HTML/CSS 渲染方案天然契合（不像 Konva 对视频不友好）。自写约 400~600 行有边界条件的几何代码，引入后约 80 行配置。此为整个 v1 计划里 ROI 最高的依赖。同时引入配套的 `react-selecto`（框选库，同作者）。

选中后元素四周显示**8 个手柄**（4 角 + 4 边中点）+ 顶部一个独立的旋转手柄（小圆点 + 引线，PureRef 同款）。所有变换规则由 `react-moveable` 实现：

**关键交互：缩放锚点跟着手柄走**

| 拖动手柄 | 锚点（不动点） |
|---|---|
| 右下角 | 左上角 |
| 左下角 | 右上角 |
| 上边中点 | 下边中点 |
| ……（任何手柄） | 对侧的对应点 |
| 任意手柄 + `Alt/Option` | **以中心为锚** |
| 任意手柄 + `Shift` | **保持长宽比**（图片默认就是这个行为；按 `Shift` 强制）|

多选状态下手柄围合**整体包围盒**；缩放时所有元素以包围盒对侧锚等比缩放（拖角默认锁比；若拆开比例会拉变形，建议默认锁，按 `Shift` 切换）。

### 3.4 旋转

- 顶部独立旋转手柄（拖动）
- 旋转锚点 = 元素中心（多选 = 整体包围盒中心）
- 按 `Shift` 吸附 15°
- 不做透视/扭曲（PureRef 也没有）

### 3.5 裁剪（矩形交互 → 旋转后呈现为多边形）

> **决策（已确认）：v1 即做**。裁剪在 UX 上**永远是矩形交互**——画布上拉出一个轴对齐矩形框；只是因为元素本身已经被旋转，矩形与元素求交后呈现为多边形（正方旋转 45° + 矩形裁 = 八边形）。

**做法**：
- 进入裁剪模式（双击元素 / `C` 键）：弹出画布坐标系下的轴对齐裁剪框，用户拖动框的边/角调节（裁剪态下**禁用**元素自身的变换手柄，避免和裁剪框手柄混淆）
- 退出时（Enter / 点别处），把"当前元素的可见多边形"与"裁剪矩形"做**多边形求交**（Sutherland–Hodgman 凸多边形裁剪算法，纯 JS 约百行）
- 元素的 `clip_polygon` 字段保存为元素**局部坐标**下的多边形顶点（一次性烘焙，跟元素一起继续被旋转/缩放）
- 渲染时图片 / 视频套上 CSS `clip-path: polygon(...)`（原生支持，性能好；对 `<video>` 同样生效）
- 可重复裁剪：再裁就是新的画布矩形 ∩ 当前多边形 → 顶点更多
- `Esc` 取消裁剪、不写入

### 3.6 层级（Z-order）

| 操作 | 快捷键 |
|---|---|
| 置顶 | `]` 多次 / `Ctrl + Shift + ]` |
| 置底 | `[` 多次 / `Ctrl + Shift + [` |
| 上一层 | `Ctrl + ]` |
| 下一层 | `Ctrl + [` |

数据上每个 `canvas_item` 存 `z`（整数），渲染按 `z asc` 排序。重排时只改涉及到的几项，不全表 reindex。

### 3.7 编组 / 解组

**评估：v1.5 做**。`Ctrl+G` / `Ctrl+Shift+G`。理由：

- 实现成本不高（item 加一个可选 `groupId`，多选时若同组就一起选）
- 但"组的旋转/缩放如何作用到子项"是一个完整子问题（要把子项的局部 transform 围绕组中心做矩阵复合），跟裁剪一样值得单独迭代
- v1 用"多选 + 一起拖"作为穷人版编组，覆盖 80% 场景

### 3.8 F 键聚焦

- **无选中**：fit 画布**所有内容**的包围盒到视口（留 10% 内边距）
- **有选中**：fit 选中项的包围盒
- 包围盒计算需要考虑旋转后的真实 AABB（取 4 角变换后求 min/max）

### 3.9 方向键 navigate

> 这个我特别想认真做——它是 PureRef 没有的、却特别贴合"看素材"的体验。

- 无选中：`←/→/↑/↓` 任一键 → 选中**最靠近视口中心的元素**作为起点
- 有选中：`←/→/↑/↓` → 选中**当前选区中心方向上最近的元素**
  - "方向上"判定：候选元素中心相对当前中心，向量与方向键 unit 向量的余弦 > 0.5（即 ±60° 内才算"在那个方向"）
  - 满足后再取距离最近
- 切换时：自动 pan 让新选中元素进入视口（不强制聚焦，避免缩放抖动）
- `Shift + 方向` 可考虑"加入选区"，v2 再做

### 3.10 其他基础

| 操作 | 行为 |
|---|---|
| `Delete` / `Backspace` | 把选中项**从画布移除**（不影响库 / 不影响其他画布） |
| `Ctrl + Z` / `Ctrl + Shift + Z` | 撤销 / 重做（v1 维护一个内存撤销栈，覆盖最近 N 步增删/移/缩/旋/裁/层级） |
| 双击元素 | 进入裁剪（v1.5）或大图详情（v1，复用现成 Detail 视图） |
| 右键元素 | `ContextMenu`：置顶 / 置底 / 复制 / 移除 / 加心 / 不感兴趣 |

## 4. 我们的两个特色（PureRef 没有）

### 4.1 视频作为画布元素

- 直接在画布上以 `<video src="serendip://video/<id>">` 渲染（HTTP Range 已支持，无新后端）
- **变换 / 旋转 / 缩放 / 裁剪 / 层级 / 选择全部一致**——视频和图片在画布里是同种"四边形元素"，只是材质不同
- 默认行为：**静音 + 自动循环**

**性能管理（v1 即做，决策已确认）**——核心规则："**出视口即暂停**"：

| 状态 | 行为 |
|---|---|
| 视口内 + 屏幕占比 ≥ 阈值（如 5%） | 自动播放 |
| 视口内 + 但太小（<5%） | 定格首帧（避免远缩时几十个视频同时跑） |
| 视口外 | **`pause()`** + 不渲染（CSS `content-visibility: auto` 或主动 unmount `<video>` 节点保留 poster） |
| 用户选中 / hover | 强制播放（即便很小） |
| 全局开关 "**全部静止**" 打开 | 一律 `pause()`，仅显示首帧 poster |

技术实现：`IntersectionObserver` 监听每个视频元素的视口可见性 + 视口尺寸阈值；状态变化触发 `play()` / `pause()`。视频太多时配合"性能模式"再降一档（首帧也用静态缩略图替代）。

**首帧来源**：复用 `serendip://thumb/<id>`（已有 webp 缩略图），定格态下直接 `<img>` 渲染，比保留 `<video>` 节点轻得多。

工具栏给一个全局开关："**全部静止（图片化）**"——长期排版时关掉所有视频播放，只看首帧。

### 4.2 摄影机手摇（Camera Shake / Live View）

> 这是 Serendip 的小彩蛋。PureRef 没有，但我们做得到，因为我们有视频元素 + 自有视口。

**v1 形态：全控制调试面板**（决策已确认）

- 工具栏一个相机图标 → 打开"手摇调试面板"（drawer 或浮动 panel）
- 暴露所有可调参数，方便用户调出他想要的手感后**记录数值**反馈给我们沉淀为预设
- 可调参数（每帧噪声叠加在视口最终矩阵上）：

| 参数 | 含义 | 范围建议 |
|---|---|---|
| `posAmplitude` | 位移振幅（px） | 0 – 50 |
| `posFrequency` | 位移频率（Hz） | 0.1 – 5 |
| `rotAmplitude` | 旋转振幅（度） | 0 – 5 |
| `rotFrequency` | 旋转频率（Hz） | 0.1 – 3 |
| `zoomAmplitude` | 缩放呼吸振幅（比例） | 0 – 0.1 |
| `zoomFrequency` | 缩放呼吸频率（Hz） | 0.05 – 1 |
| `noiseSeed` | 噪声种子 | 任意 |
| `masterIntensity` | 总强度（0–200%） | 0 – 2 |

- 面板底部一个 **"复制当前参数为 JSON"** 按钮 + **"另存为预设…"** 输入框（v1 把命名预设存在 localStorage 即可，无需 schema）
- 等用户调好若干常用预设后，反馈给我们写死成内置预设（`关闭` / `轻微手持` / `走动` / ...）

**算法**：1D simplex noise（手写或抄一份 ~30 行的实现，无新依赖）按时间驱动 `Δx, Δy, Δrotate, Δzoom`；每个维度用独立的 noise offset 避免同步。`requestAnimationFrame` 驱动，停用时归零。

**约束**：手摇启动期间禁用元素编辑（变换手柄隐藏 + 拖动锁定），避免在抖动里精修；可单独在面板内"暂停手摇"以便短暂操作。

## 5. 边界 / 空态

- **无画布**：侧栏底部一个"+ 新建画布"占位按钮；瀑布流卡片"加入画布"图标点击弹出"先建一个画布"提示
- **空画布**：中央提示"把图片或视频拖进来开始"+ 一个示意箭头指向左侧栏的瀑布流（用户从那拖过来）
- **元素源文件丢失**（被监听器标记 `is_missing`）：画布元素显示灰色占位 + ⚠️，仍可移动/删除，不可裁剪/编辑
- **画布内素材数过大**（>500）：v1 不做硬限制，但工具栏给一个"性能模式"——拖动时降低非选中元素的渲染质量（CSS `image-rendering: pixelated` 配合缩放）
- **删除画布**：与删除分类一致，`ON DELETE CASCADE` 清 `canvas_items`；不影响 `media_files`

## 6. 数据模型（粗略，技术评审时再定字段类型）

```
canvases
  id, name, position,            // 列表序，类比 categories
  viewport_x, viewport_y, viewport_scale,   // 上次离开时的视口
  created_at, updated_at

canvas_items
  id, canvas_id, file_id,
  x, y,                          // 中心点世界坐标
  w, h,                          // 缩放后的尺寸（基础宽高存 file 的原始 meta）
  rotation,                      // 弧度
  z,                             // 层级
  clip_polygon (json|null),      // 局部坐标多边形顶点（v1）
  group_id (int|null)            // v1.5
  // 不加 UNIQUE(canvas_id, file_id) —— 同一文件可在同一画布多次添加（拼图常用，PureRef 同款，已确认）
```

**全局状态（zustand，未持久化）**：`currentCanvasId: number | null` —— §2.4 的"当前画布"指针。它不进库，重启 app 后回到 `null`（或可持久化到 settings 表，待评审）。

**坐标空间边界说明**：画布不是"无限画布"（对比 tldraw / Excalidraw 的 Canvas 2D 路线），而是**有限但巨大的自由工作区**（世界坐标 ±2^53 安全整数，实际 ±百万像素够用）+ 自由视口 pan/zoom。用户不会感知边界（拖到 `x: 50000` 放图、再拖回原点完全没问题）；只有刻意摆几千张图横跨百万像素时才遇到理论边界（且遇到的不是坐标问题，是 DOM 节点多卡住了）。技术上称"自由二维平面"比"无限画布"更准确。

## 7. 技术落点（复用为主）

| 能力 | 复用 / 新增 |
|---|---|
| 路由 | **复用** `useLibraryStore.view`，加 `{kind:'canvas', id}` 分支 |
| 侧栏入口 | **复用** `CategoryList` 的 sortable + droppable 模式，几乎复制粘贴 |
| 添加按钮 / picker | **复用** `ContextMenu`、`SelectionToolbar`、`MediaCard` 已有的 hover overlay |
| 拖拽进画布 pill | **复用** 现成 `DndContext` + `pointerWithin` 严格命中 |
| 视口 pan/zoom | **新写**，约 100 行（监听 wheel/pointer，输出 transform 矩阵） |
| 元素渲染 | **HTML/CSS** 方案（每元素一个 `<div>` 内含 `<img>` 或 `<video>` + `transform: translate rotate scale`），不引入 Konva（Konva 在视频上路要走逐帧 drawImage，丢音频且复杂；HTML/CSS 让视频"自由"得多） |
| 选择手柄 + 变换 | **引入 `react-moveable`**（8 手柄 + 旋转柄 + 锚点映射 + Alt/Shift 修饰键 + 多选包围盒，~80 行配置替代 400~600 行自写几何） |
| 框选 | **引入 `react-selecto`**（moveable 配套，同作者） |
| 多边形裁剪 | **新写**（v1）Sutherland–Hodgman ~100 行，渲染走 CSS `clip-path: polygon()` |
| 撤销栈 | **新写**，纯前端命令模式 ~30 行，比 zustand 中间件更可控 |
| 摄影机手摇 | **新写**，1D simplex noise + `requestAnimationFrame`，~50 行无依赖 |
| IPC | 新增 `createCanvas` / `listCanvases` / `renameCanvas` / `deleteCanvas` / `reorderCanvases` / `addItemsToCanvas` / `removeItemsFromCanvas` / `updateCanvasItem(s)` / `updateCanvasViewport`。**契约照搬 categories 的命名风格**，全部走 `IPC.*` 常量。 |
| DB 迁移 | 新增 `migration 4`：`canvases` + `canvas_items`（不动既有表） |

> **新增依赖**：`react-moveable` + `react-selecto`（KaKao 维护，npm 周下载 50 万+，成熟稳定）。变换手柄是整个画布交互的核心，引入后大幅降低几何代码的边界条件复杂度，且与 HTML/CSS 渲染方案天然契合（不像 Konva 对视频不友好）。其余新逻辑都在现有栈（React 18 + Zustand + dnd-kit + 原生 DOM/SVG）上落地。

## 9. 已确认决策（v1 基线）

1. **同一画布允许同一文件多次添加**（拼图常用，去掉 `UNIQUE(canvas_id, file_id)`）

## 10. 侧栏伸缩性（项目多了之后怎么办）

> 你提的真实顾虑：分类 + 画布以后必然会增长，左侧栏现在的"全部展开 + 单层列表"扩展性堪忧。下面是 v1 / v1.5 / v2 的渐进策略。

### 10.1 v1 即做：分组折叠 + 平滑滚动

- **分类 / 画布两个分组都做成可折叠的 section**（点 caret ▶ / ▼ 收起展开），状态持久化到 `useUiStore`（localStorage）
- 默认状态：用户没建过画布时画布组**收起**（且只显示一个"+ 新建"按钮占位）；建过则**展开**
- 每个分组**自身可滚动**：列表过长时分组内部滚动（`overflow-y: auto` + `max-height`），不让整个侧栏失去导航锚点
- 当前画布 / 当前分类自动滚到分组可视区（`scrollIntoView({ block: 'nearest' })`）

### 10.2 v1 即做：稳定的视觉层次

侧栏从上到下保持稳定的"区"——**导航区永远在屏幕上方**：

```
┌──────────────┐
│ 探索          │  ← 顶部导航区（固定不动）
│ 喜欢          │
│ 评审          │
├──────────────┤
│ ▼ 分类（12） │  ← 折叠分组（自滚动）
│  ├ 旅行       │
│  ├ ...        │
├──────────────┤
│ ▼ 画布（5）  │  ← 折叠分组（自滚动）
│  ├ 灵感板 ●  │  ← ● 表示当前画布
│  ├ ...        │
├──────────────┤
│ + 新建        │  ← 底部行动区（新建分类 / 新建画布）
│ ⚙ 设置       │
└──────────────┘
```

分组标题右侧带 `(12)` 计数 + caret，**让用户始终知道有多少**，避免折叠后失忆。

### 10.3 v1.5：搜索 / 过滤框

分组标题旁加放大镜 → 展开内联搜索框（仅过滤本分组的项），按名称模糊匹配。条目超过 ~20 个时强烈推荐用搜索而不是滚动找。

### 10.4 v1.5：拖拽嵌套（folder）

- **轻量嵌套**：分类 / 画布支持一层"组"（folder）—— 拖一个 pill 到另一个 pill 上即合并成 folder（参考 iOS 桌面）
- folder 自身可折叠 / 重命名 / 删除（删除 folder 不删子项，子项回到顶层）
- 不做无限嵌套（两层就够 99% 场景，更深层难导航）
- Schema 影响：`categories` / `canvases` 加一个 `parent_id (int|null)` 即可

### 10.5 v2：侧栏宽度可调 + 图标态

- 拖拽侧栏右边界改宽（min 200 / max 360）
- 拖到最窄时自动切到"**图标态**"：只剩图标 + 数字徽章，hover 弹出全名 tooltip，类似 VSCode 活动栏
- 图标态时分类/画布折叠为单图标，点击弹出二级面板列出条目（同 VSCode 文件浏览器交互）

### 10.6 不做的事

- ❌ **多面板 / 标签页化侧栏**（左中右三栏式 IDE 布局）：素材浏览器不是 IDE，加重复杂度收益低
- ❌ **无限嵌套树**：树太深用户会迷路；两层足矣
- ❌ **强制按字母 / 时间排序**：用户手动排序的 affordance 比自动排序更符合"个人收藏"心智
